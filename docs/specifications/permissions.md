# 权限规范

## 文档状态

本文从 Gateway 身份、运行门禁和生命周期资料中提炼候选跨产品规则，尚待安全团队批准，保持
`draft`。领域专用权限清单和产品流程不在此作出承诺。

## 共享授权模型

| 概念 | 含义 |
| --- | --- |
| 主体 | 被认证并请求执行操作的人、服务或受控自动化身份。 |
| 资源 | 需要保护的业务对象、配置、数据或运行能力。 |
| 操作 | 主体尝试对资源执行的明确行为。 |
| 作用域 | 操作被允许的资源边界、租户边界、时间边界或其他约束。 |
| 授权 | 根据主体、资源、操作和作用域作出的允许或拒绝判断。 |

认证用于确认主体；授权用于判断该主体能否在给定作用域内执行操作。两者不得相互替代。

## 候选规则

1. 默认拒绝。无法证明明确授权、资源归属、作用域或必要控制状态可信时，服务端拒绝操作。
2. 最小权限。角色、服务身份、令牌和自动化能力只授予完成预期工作所需的最小操作和最小范围，
   并避免用宽泛的管理员权限替代精确授权。
3. 服务端为权威。客户端的隐藏、禁用或提示只能改善体验，不能代替服务端对每次受保护操作的
   授权校验。
4. 授权结果可审计。对敏感资源的允许、拒绝、委托、提升、撤销和恢复应保留最小必要的主体、
   操作、资源、作用域、结果和关联标识，且不得记录凭据明文。
5. 权限变更安全收敛。授权或运行控制状态无法验证时，不得以缓存、过期配置或客户端声明继续
   放行；已经开始的工作按其已授权的生命周期收口，并记录可恢复事实。
6. 兼容性显式处理。权限标识符、角色含义和作用域变化必须评估对现有主体与集成方的影响，并
   通过迁移或弃用安排处理，不能静默扩大权限。

## 用户可见行为

对外拒绝应使用稳定、可理解且不泄露资源存在性、内部拓扑或其他主体信息的语义。产品可以按
体验需要选择隐藏、禁用或申请权限入口，但必须与服务端的实际授权结果一致。

## 迁移来源与审阅

Gateway 的身份与 API Key 阶段资料、`DEC-040`（accepted，2026-07-21）以及生命周期审计是本
文的迁移来源。它们不等同于跨产品权限模型；安全团队批准前，本文不构成 `active` 规范。

## 边界

本文定义公共权限模型。领域专用权限清单和业务流程留在对应产品领域。
