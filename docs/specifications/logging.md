# 日志规范

## 文档状态

以下规则由 Gateway 可观测性资料迁入，尚待可靠性团队批准，全部保持 `draft`。本文定义跨产品
契约，不规定特定日志平台、查询、保留期或仪表盘。

## 结构化事件契约

每条诊断或审计事件应使用结构化字段，并在适用时包含：时间、严重级别、事件名称、服务或
组件、环境、事件结果，以及可安全记录的关联标识。进入平台的请求应携带或生成受格式约束的
`correlation_id`；有独立业务生命周期时，使用单独的 `request_id` 或操作标识，避免把不同语义
混为一个 ID。

认证或资源信息仅在诊断必需且可安全记录时加入，并使用稳定内部标识或最小化形式。事件字段
应解释为事实或判定，不应把未经确认的推测写成成功结果。

## 关联、指标与审计

- `correlation_id` 用于串联一次端到端交互；业务操作 ID 用于串联其跨进程、异步或恢复生命周期。
- 关键状态转换、授权判断、外部调用结果、失败分类、补偿和恢复结果应可关联并保留必要的
  审计上下文。
- 指标标签只能使用有界、受控且非敏感的维度。不得使用原始请求 ID、凭据、用户输入、完整 URL
  或其他高基数值作为通用标签。
- 采样、保留、访问、删除和不可变性要求应由数据分类及负责人另行批准；采样不能破坏需要
  审计的业务事实。

## 敏感信息与错误

默认不得记录请求体、用户提示词或其他用户内容、API Key、密码、会话令牌、Authorization 头、
上游凭据、密钥材料，或可直接暴露内部地址和拓扑的原始错误正文。确有受控审计需要时，应先
定义最小字段、访问边界、保留期和脱敏方式。

对外错误只表达公开契约允许的信息，并可返回安全的关联标识供支持人员诊断；内部日志应将
失败分类与敏感根因分离。堆栈、原始上游错误和调试载荷不得默认进入客户可见响应。

## 验证

实现应验证关联标识的传播、敏感字段不被记录、错误脱敏，以及指标标签的基数限制。具体测试
和运行查询属于实现仓库资料，不在本文维护。

## 迁移来源与审阅

Gateway Phase 08（可观测性与稳定性）和 `GATEWAY_LIFECYCLE_AUDIT` 是本规范的迁移来源；
其中的字段、实现路径、指标名称和运行记录未直接迁入。可靠性团队批准前，本文不构成 `active`
规范。

## 边界

供应商配置、仪表盘查询和产品运行手册属于对应实现的运营资料。
