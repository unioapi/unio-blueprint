# Admin（管理后台）概览

## 产品陈述

Admin 是 UnioAPI 面向内部运营人员的工作台：它把供应、凭据、产品配置、账务事实和运行事实组织为可审计的操作与判断，帮助运营在不暴露给客户内部拓扑的前提下维持可用、可解释的服务。

## 问题

运营配置、真实上游检测、故障事实、账务事实和历史数据不能由单一“健康”标签替代。运营人员需要既能安全地修改供给，又能区分配置、凭据、容量、熔断、同步和历史表现，并追溯其影响。

## 受众与任务

| 受众 | 任务 | 当前困难 |
| --- | --- | --- |
| 运营人员 | 维护 [Provider、Provider Origin、Channel 与 Route](../gateway/glossary.md) 的可用配置 | 配置变更、凭据状态和故障域必须彼此可区分。 |
| 运营人员 | 检查请求、用量、结算与经营事实 | 金额、延迟和运行态不能被不透明的聚合分数掩盖。 |
| 运营人员 | 归档不再使用的供给，同时保留历史解释能力 | 硬删除会破坏历史关联与账务解释。 |

## 预期结果

- 运营人员能在受控流程内创建、修改、归档和恢复供给配置。
- 凭据变更在真实客户流量使用前完成检测，且检测结果可追溯。
- 页面以可核验的客观事实支撑判断，历史经营金额不跨币种相加。

## 自有能力

- 内部供给与运行配置管理，以及安全的凭据轮换与渠道检测。
- 请求、用量、账务、结算恢复和运营运行态的查询与可视化。
- 面向运营的经营驾驶舱、分析中心和实时监控入口。
- 面向内部操作的归档、恢复和风险提示。

## 非目标

- 客户自助管理、客户可见的线路选择或公开 Gateway API。
- 直接执行 Gateway 路由、结算、熔断或准入控制。
- 以模型能力声明作为请求准入闸门，或恢复已被取代的渠道能力收紧。
- 用主观健康分数或历史分桶代替当前可服务性判断。

## 主要用户旅程

1. 运营人员从 Provider 列表查看其 Provider Origin 摘要，创建或维护 Origin 与 Channel。
2. 运营人员轮换 Channel 凭据；系统先保存并暂停新配置，再以真实上游检测决定是否恢复可路由状态。
3. 运营人员查看渠道、源站和线路的客观运行事实，定位是凭据、容量、熔断、同步还是历史质量问题。
4. 运营人员归档不再使用的实体，必要时迁移线路绑定；恢复后按受控状态重新启用。
5. 运营人员在经营驾驶舱先判断经营状态，再下钻分析或进入实时监控。

## 边界与依赖

| 领域 | 关系 | 所有权边界 |
| --- | --- | --- |
| Gateway | 提供路由、请求、账务和运行态的事实 | Admin 读取或发起受控管理动作，不重定义 Gateway 行为。 |
| Console | 面向客户的控制台 | Admin 不承载客户自助流程。 |
| 平台质量属性 | 约束安全、可观测性、可靠性与易用性 | Admin 在 [质量要求](quality.md) 中细化运营场景。 |

## 成功指标

| 指标 | 基线 | 目标 | 证据来源 | 复审周期 |
| --- | --- | --- | --- | --- |
| 凭据轮换后未经验证即被路由的次数 | 待核验 | 0 | 凭据轮换与检测记录 | 每月 |
| 可用事实被主观健康标签替代的页面 | 待核验 | 0 | 页面验收与运行态契约 | 每次发布 |
| 经营金额跨币种相加的卡片 | 待核验 | 0 | 看板验收 | 每次变更 |

## 风险与假设

- Gateway 来源中“已实现”与当前长期产品承诺不同；实现状态须按路线图核验。
- 多管理员授权、审计和会话模型不在本次迁移中批准，后续扩大访问面前必须另行决策。
