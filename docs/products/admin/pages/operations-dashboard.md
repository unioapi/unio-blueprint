# 页面设计：经营驾驶舱

## 目的

让运营人员在首屏快速判断经营状态，并以客观数据下钻到分析中心或实时监控，而不是将所有明细堆入首页。

## 用户与入口

| 用户 | 入口 | 预期上下文 |
| --- | --- | --- |
| 运营人员 | Admin 首页 | 需要在短时间内判断经营变化和是否需要下钻。 |
| 运营人员 | 异常、渠道或利润分析入口 | 已在排查具体经营或运行问题。 |

## 信息层级

1. 首屏决策层：状态 Banner、当前窗口与等长紧邻上期比较、8 项 KPI。
2. 二级分析中心：利润、渠道、模型、缓存、用户和异常中心。
3. 实时监控页：QPS、TPS、RPM、TPM、P99 与错误率，使用独立的实时数据源。

首屏 8 项 KPI 为收入、毛利、利润率、缓存贡献（估算）、请求数、成功率、异常请求和客户余额池。首屏不放明细表、排行榜、Token 拆解或逐渠道明细。

## 数据与权限

| 数据或操作 | 来源或权威位置 | 可见性或权限 | 新鲜度 |
| --- | --- | --- | --- |
| 经营 KPI 与历史趋势 | [运营可观测性](../features/operations-observability.md) | 授权运营人员 | 明示查询窗口与数据更新时间 |
| 实时运行指标 | 运营可观测性 | 授权运营人员 | 明示为实时数据 |
| 下钻分析 | 路线图中的分析中心 | 授权运营人员 | 与其数据源一致 |

## 交互

- 选择时间窗口时，系统以等长紧邻窗口计算比较，保留两段数据的可解释性。
- 金额卡按币种分开展示；不得提供隐式汇率换算或跨币种总额。
- 缓存贡献卡始终标记“估算”，并与账本事实视觉区分。
- Banner 和 KPI 只提供下钻入口，不用主观健康标签表示当前运行状态。

## 页面状态

| 状态 | 必备表现 | 可用操作 |
| --- | --- | --- |
| 加载 | 显示窗口和结构占位，不显示过期 KPI 为当前值 | 调整窗口或等待 |
| 无数据 | 明确指定窗口没有事实，不构造零以外的推断 | 选择其他窗口 |
| 多币种 | 按币种拆卡或展开 | 在单币种内比较 |
| 数据不完整 | 标明缺失来源和影响范围 | 下钻或查看数据新鲜度 |
| 运行态故障 | 显示客观基础设施故障与准入影响 | 进入实时监控 |

## 无障碍

每张 KPI 卡有可读名称、数值单位和比较基准；图表提供数据表或文本摘要；状态 Banner 通过非颜色文字和状态区域表达；所有下钻入口可键盘访问。

## 验收标准

- [ ] 首屏只包含决策层信息，不成为明细仓库。
- [ ] 金额不跨币种相加，缓存贡献始终标为估算。
- [ ] 实时监控和数据库经营聚合有清晰的数据源边界。
- [ ] 页面不展示健康分桶，且能区分基础设施故障、无样本和历史事实。
