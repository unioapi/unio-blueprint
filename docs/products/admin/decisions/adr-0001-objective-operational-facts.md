# ADR-0001：经营驾驶舱采用客观运营事实

## 背景

来源中的早期 Admin 页面曾根据历史成功率生成健康分桶。该标签会把主动检测、当前 breaker、容量、同步状态和历史表现混为一谈，不能解释当前是否可服务。经营首页同样不能把所有指标和明细放在同一层，也不能跨币种相加账务事实。

## 决策驱动因素

- 运营判断必须能回到可验证的原始事实。
- 当前运行状态与历史经营趋势需要明确区分。
- 金额与利润展示必须可审计，不受隐式汇率影响。

## 备选方案

### 方案：保留主观健康标签

将错误率、检测和延迟按人工阈值合成为绿色、黄色或红色标签。

**优点**

- 页面表面更简短。

**缺点**

- 会掩盖不同故障原因和时间尺度，且可能与当前硬门禁矛盾。

### 方案：使用客观事实与分层驾驶舱（选中）

并列展示事实，将经营决策、分析和实时运行分层。

**优点**

- 可解释当前不可服务、基础设施故障、无样本和历史表现之间的差异。
- 减少首页信息负担，同时保留可下钻的分析能力。

**缺点**

- 需要维护清楚的数据新鲜度、数据源和下钻边界。

## 决策

- 删除主观 `healthy`、`degraded`、`unhealthy`、`no_data` 健康分桶及其配置、筛选、卡片和徽章。
- Admin 并列展示凭据状态、主动检测、breaker、错误率与样本、Channel 最近 30 分钟平均上游 TTFT、请求
  Gateway TTFT、attempt 上游 TTFT、流式/非流式总耗时、容量、同步、五项评分计算过程、最终权重和实际
  分流等客观事实；Gateway TTFT 与上游 TTFT 不得互相代填或合并。
- “当前可服务/不可服务/基础设施故障”仅由当前硬门禁和运行态 readiness 推导；Redis 或运行态基础设施故障必须说明准入已拒绝，不能等同于无样本。
- 经营驾驶舱分为决策层、分析中心和实时监控页。首页只展示 8 项 KPI、等长窗口比较和状态 Banner。
- 金额按币种分组，不引汇率或跨币种相加；缓存贡献是反事实估算，必须明确标识。

本 ADR 是 Blueprint 提议，来源的 accepted 或 implemented 标记不等同于本决策已获 Blueprint 批准或已实现。

## 影响

### 正面影响

- 运营人员能定位凭据、容量、源站、渠道和同步问题，而非读取不可解释的汇总标签。
- 经营数据的币种、账本事实和估算边界更清晰。

### 负面影响

- 页面需要呈现更多上下文，并对无样本和数据过期做明确设计。

### 中性影响或后续工作

- 分析中心、rollup 和实时监控的实现状态需按路线图核验。
- 供应商余额、在线用户、排队请求等无数据源指标不纳入当前驾驶舱。

## 风险与缓解措施

| 风险 | 缓解措施 | 负责人 |
| --- | --- | --- |
| 历史分桶重新进入页面 | 页面和契约验收禁止健康分桶字段 | 管理后台团队 |
| 旧运行态被误作当前事实 | 展示版本与新鲜度，stale 不显示旧运行态 | 管理后台团队、网关团队 |
| 估算与账本金额混淆 | 缓存贡献强制标为估算且不并入利润 | 管理后台团队、财务负责人 |

## 落地与验证

验证页面不存在主观健康字段；基础设施故障、无样本和当前不可服务可区分；请求 Gateway TTFT 与
attempt/Channel 上游 TTFT 标明各自口径，非流式不显示 TTFT；五项评分展示完整计算过程；金额不跨币种
相加。具体实现状态不由本 ADR 声明，见[路线图](../roadmap.md)。
