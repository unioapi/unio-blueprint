# 平台质量属性

## 文档状态

本文从 Gateway 迁移资料归纳候选质量场景。场景可指导评审和测试设计，但尚无负责人批准的
数值目标、服务等级或优先级，因此保持 `draft`。

## 候选质量场景

| 属性 | 场景与期望响应 | 可观察证据 | 目标与负责人 |
| --- | --- | --- | --- |
| 可靠性与恢复性 | 进程、网络或共享运行态发生故障时，阻止无法安全验证的新操作；已开始的业务事实继续完成、补偿或留下可恢复记录。 | 终态、补偿记录、幂等结果、恢复审计、健康状态。 | 指标阈值、恢复时间和负责人待定。 |
| 可用性 | 必需依赖、配置和运行态完整时才宣告 `readiness`；进程仍可执行诊断与恢复时维持 `liveness`。 | 就绪状态、依赖健康、恢复完成证据、流量门禁记录。 | 可用性目标和依赖等级待定。 |
| 协议兼容性 | 公开协议或集成契约演进时，保持已支持行为，或提供明确的弃用、迁移和安全错误语义。 | 版本化契约、兼容性场景、客户端可观察的错误分类。 | 支持范围、版本窗口和负责人待定。 |
| 可观测性 | 一次端到端工作可通过请求标识、关联标识和必要的业务标识串联；关键状态转换、失败分类和恢复结果可诊断。 | 结构化事件、关联链路、低基数指标、审计记录。 | 覆盖率、保留期、采样率和负责人待定。 |
| 隐私与安全 | 日志、指标、追踪和外部错误不默认暴露凭据、认证材料、用户内容、个人数据或内部拓扑。 | 数据分类、脱敏验证、访问审计、泄露演练。 | 数据分级、保留期和负责人待定。 |
| 性能与容量 | 流量、外部调用、持久化和恢复压力下，系统的超时、排队和资源使用可测量，并避免把不可用依赖放大为级联故障。 | 延迟、错误、饱和度、队列/租约和依赖状态。 | 容量基线、延迟目标和负责人待定。 |
| 可维护性 | 跨组件变更具有明确边界、兼容性和回滚/恢复考虑；依赖与核心逻辑均可审计。 | 评审记录、变更计划、测试证据、依赖清单。 | 覆盖门槛和负责人待定。 |

## 度量与验收规则

每个获批质量目标应补充触发条件、期望响应、测量方法、数据来源、目标值、负责人和复审
周期。指标应区分业务审计与运行度量：请求标识、API Key、用户输入和完整 URL 等高基数或
敏感值不得直接成为通用指标标签。

测试和运行报告可以作为证据，但测试通过不等同于质量目标已经批准。具体领域的阈值与验收
场景应在对应领域文档细化，并链接回本文。
