# 平台架构总览

## 文档状态

本文根据已经确认的产品决策和当前可验证的产品行为整理，供产品负责人审核。
在审核完成并补齐对应的全局决策记录前，本文保持 `draft`，不把待规划能力描述成
已经交付的事实。

## 产品陈述

UnioAPI 是一个商业化、多服务商、多渠道的 AI API 接入与运营平台。它面向需要调用
AI 模型的开发者和应用团队，提供统一、稳定、可计费的 API；同时为平台运营人员提供
管理模型供给、线路、成本、客户使用和账务事实所需的运营能力。

客户不需要直接管理每个上游服务商的协议差异、访问凭据和故障切换。客户使用
UnioAPI 的 API Key 和公开协议访问模型，平台在客户所选线路的边界内完成协议适配、
候选过滤、流量调度、失败切换、用量计量和账务结算。

UnioAPI 当前第一产品线是**分档线路网关**，不是向客户公开全部上游渠道的透明聚合
市场。客户选择线路和模型，只看到所在线路及该线路下模型的最终售价，不直接看到
服务商、上游源站、渠道或内部定价倍率。

## 要解决的问题

### 客户侧

直接接入多个 AI 服务商时，开发者通常需要分别处理协议、模型标识、认证方式、可用性、
限额和账单。上游渠道发生故障或调整时，客户应用也可能被迫修改配置或承担不可预测的
调用结果。

UnioAPI 的目标是让客户围绕一套稳定的公开契约进行集成，并由平台吸收上游供给变化带来
的复杂性。客户选择的线路决定适用的模型售价和内部供给边界；平台只能在线路边界内
调度，不能将请求切换到客户未选择的其他档位。渠道池、定价倍率和成本结构属于内部
运营事实，不向客户公开。

### 运营侧

经营多服务商、多渠道的 AI API 产品，需要统一管理模型供给、上游凭据、协议适配、
渠道状态、路由范围、售价、成本、客户余额、请求事实和账本流水。如果这些事实分散在
配置文件、人工表格或不同系统中，平台将难以稳定路由、核算毛利和解释历史账单。

UnioAPI 将这些概念纳入同一产品模型，使运营人员能够控制供给和风险，同时让客户侧
保持简单、稳定。

## 主要受众

| 受众         | 主要任务                         | UnioAPI 提供的价值                         |
| ---------- | ---------------------------- | ------------------------------------- |
| 客户开发者与应用团队 | 将 AI 模型接入应用、自动化工具或 Agent 工作流 | 使用统一协议和 API Key 调用模型，不直接处理上游渠道差异      |
| 客户账户管理者    | 管理 API Key、线路、余额、用量和请求记录       | 通过客户自助产品管理使用边界；具体交付范围仍需在 Console 领域确认       |
| 平台运营人员     | 管理服务商、渠道、模型、线路、价格、客户和账务      | 在内部运营界面维护供给、配置产品档位并排查经营与运行问题          |
| 平台维护者      | 维护公开契约、路由可靠性、计费正确性和可审计性      | 以统一的平台事实和质量约束控制跨领域演进                  |

## 核心产品模型

| 概念                     | 含义                             | 客户边界                                       |
| ---------------------- | ------------------------------ | ------------------------------------------ |
| Protocol（协议）           | 客户程序与 UnioAPI 交换请求和响应时遵循的公开契约  | 是                                          |
| Model（模型）              | 客户请求的模型标识及其能力；内部关联基准价格         | 客户看到所在线路下的模型最终售价，不看到内部基准价格                 |
| Route（线路）              | 客户使用的产品档位；内部关联定价倍率、渠道池和线路内调度模式 | 客户可选择并看到线路，不看到倍率、渠道池或调度规则；自助入口待 Console 交付 |
| User Account（用户账户）   | 当前个人账户模式下的认证、余额和 API Key 归属主体     | 是                                          |
| API Key                | 客户端应用访问平台的凭据，当前关联用户账户并显式绑定线路   | 是                                          |
| Provider（服务商）          | 上游供应商身份或结算主体                   | 否                                          |
| Provider Origin（上游源站） | 服务商的一条 API 根地址及其公共故障边界           | 否                                          |
| Channel（渠道）            | 上游源站下的一组账号级上游访问与路由事实           | 否                                          |
| Request（请求）            | 一次客户调用的端到端事实                   | 仅应向客户展示自身记录；自助入口尚未交付                       |
| Attempt（尝试）            | 请求在线路内对某个候选渠道发起的一次上游调用         | 默认不暴露内部拓扑                                  |
| Usage（用量）              | 输入、输出、缓存和推理等可计量使用事实            | 客户自助查看范围待 Console 确认                       |
| Ledger（账本）             | 余额冻结、扣费、释放、核销等资金事实             | 平台维护完整审计；客户自助查看范围待确认                       |

平台通用术语属于[平台词汇表](glossary.md)；Gateway 领域对象的迁移草案见
[Gateway 词汇表](../products/gateway/glossary.md)。本文只说明理解平台所需的关系，不建立第二套定义。

## 核心交互模型

```text
客户应用
  -> 使用 API Key 和公开协议请求模型
  -> 解析 API Key 关联的线路
  -> 在线路显式渠道池内筛选能够服务该模型的候选
  -> 按线路策略选择候选，并只在线路内执行失败切换
  -> 返回与客户请求协议一致的结果
  -> 根据用量、锁定售价和实际渠道成本完成结算与审计

平台运营人员
  -> 维护服务商、上游源站、渠道、模型和线路
  -> 维护模型基准价、线路倍率和渠道成本
  -> 查看请求、用量、余额、账本和运行证据
```

这个模型包含以下产品边界：

- 线路的显式渠道池是调度边界，未加入当前线路的渠道不能参与请求。
- `balanced` 线路可以在池内调度并执行失败切换；`fixed` 线路只使用指定渠道。
- 线路内没有可用候选时，请求失败；平台不能跨线路切换或暗中降低客户所选档位。
- 服务商、上游源站和渠道是内部供给概念，不作为客户选购界面。

## 公开协议边界

当前已经确认的公开协议范围包括：

- OpenAI Chat Completions；
- OpenAI Responses API，包括面向 Codex 的兼容行为；
- Anthropic Messages；
- 受客户身份和线路约束的模型目录查询。

OpenAI 与 Anthropic 是彼此独立的公开协议族。平台可以在协议族内部适配不同上游，
但不能把一种客户协议隐式路由到另一种协议类型的渠道。

公开协议的具体字段、错误和兼容性要求属于
[API 风格规范](../specifications/api-style.md)和 [Gateway（网关）领域](../products/gateway/README.md)，
本文不维护接口清单。

## 分档线路与商业模型

### 客户购买的产品

客户购买的是**某条线路下的模型调用能力**，不是某个具体上游渠道。一个 API Key 关联
一条线路；同一模型可以因线路不同而具有不同的价格和供给范围，但模型标识本身不需要
为了表达档位而改变。

线路是客户侧产品概念，但当前客户自助入口尚未交付，现有线路和 API Key 由内部运营
能力维护。Console 落地后如何让客户选择或变更线路，仍需在对应产品领域确认。

### 售价与成本

客户侧只展示所在线路下各模型的最终售价。模型基准价、线路倍率、渠道成本和平台毛利
均为内部运营事实，不得出现在面向客户的 Console、公开 API 或 Documentation Site 中。

平台内部当前确认的定价关系是：

```text
客户售价 = 模型基准价 x 线路倍率

渠道成本 = 模型基准价 x 渠道成本倍率 x 充值倍率
        或渠道与模型的绝对成本覆盖
```

客户售价按线路、模型和生效时间锁定。线路内失败切换命中成本不同的渠道时，客户售价
不随命中渠道变化；成本变化影响平台毛利，不改变本次客户账单。

平台分别记录售价、成本、用量和相关快照，使历史结算可以根据当时事实解释和复算。
金额与账本属于平台最终事实，不能由临时运行状态代替。

## 平台职责

UnioAPI 负责以下平台级结果：

- 为客户维护稳定、明确的公开 API 契约。
- 将上游协议和渠道差异隔离在客户契约之后。
- 在客户所选线路内完成候选筛选、调度和失败切换。
- 维护模型、线路、价格、成本和客户使用之间的一致关系。
- 记录请求、尝试、用量、价格、成本和账本事实，支持审计与问题解释。
- 保护客户凭据和上游凭据，不向公开响应泄露内部拓扑或上游敏感信息。
- 面向客户只提供线路及其模型最终售价，不暴露模型基准价、线路倍率、渠道成本或毛利。
- 为内部运营和未来客户自助产品提供同一组业务事实，而不是建立相互矛盾的数据副本。

## 当前边界与非目标

- 当前不向客户展示或开放选择具体 Provider、Provider Origin 或 Channel。
- 当前不向客户展示模型基准价、线路倍率、渠道成本或平台毛利；客户只知道所在线路下
  模型的最终售价。
- 当前不提供透明展示所有渠道及渠道价格的聚合市场；该方向仅作为远期第二产品线保留，
  没有已批准的范围或交付时间。
- 当前不允许请求跨线路调度或在失败时自动降到其他档位。
- 当前身份和线路边界是 `User Account -> API Key -> Route`。Project 是历史已移除概念，不属于
  当前产品模型；未来若出现新的应用或用量归集需求，必须另立决策定义，不从历史资料恢复。
- Console 的客户自助流程尚未交付，在线支付、客户自助充值和发票能力也不在本文中作出承诺。
- Website、Documentation Site 和 SDK 是独立产品领域，不能因为目录已经建立就推断其功能、
  页面或发布时间。
- 具体进程、源码结构、数据库表、部署方式和仓库边界不属于本文。

## 已确认事实与演进边界

- 当前公开产品以 OpenAI 和 Anthropic 协议族为主，已确认的上游适配包括 OpenAI、
  Anthropic 和 DeepSeek；这不代表平台承诺支持所有服务商。
- 模型参考目录与正式对外模型是不同职责：外部目录可以提供采纳素材，但运行和售卖事实
  必须由平台运营明确维护。
- 当前可验证的交付集中在 Gateway 和 Admin，两者仍在持续建设和可靠性收口；其他产品领域
  仍需分别定义并验收。
- 路由可靠性和多实例运行控制仍在持续收口，因此本文只固定产品不变量，不固化当前内部
  实现机制。

具体交付顺序属于[平台路线图](../roadmap/platform-roadmap.md)，实现进度属于对应实现项目，
不在本文重复维护。

## 审核重点与待解决问题

以下内容尚无足够事实支撑，本文没有替产品负责人作出结论：

1. 首批目标客户是否需要进一步限定为个人开发者、Agent 工具用户、AI 应用团队或企业客户。
2. 对外线路应采用哪些商品名称，以及不同线路是否承诺可用性、性能、供应商类型或服务等级。
3. Console 首个版本的自助范围，以及注册、自助充值、在线支付、发票和团队协作的优先顺序。
4. 透明聚合市场作为远期第二产品线重新进入规划的触发条件。
5. 平台级成功指标、基线、目标值、证据来源和复审周期。

这些问题在产品负责人确认后，应分别进入[平台愿景](vision.md)、
[平台路线图](../roadmap/platform-roadmap.md)或对应的[全局决策](../decisions/README.md)，
避免在多个产品领域重复维护。
